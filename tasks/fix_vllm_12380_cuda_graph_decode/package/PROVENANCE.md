# Provenance: how these files relate to the authors' copies

The authors' working copy is `/home/coder/work/p2-port/` on their pods (`harness_iso12380/`, `tasks/iso12380/`,
`ops_iso12380/`, `scripts/stage_tmp.sh`, `screen/setup_prs.sh`, `screen/fetch.py`), read on 2026-11-24.

- `provenance/authors.sha256`: sha256 of each authors' file as found there.
- `provenance/authors_scorer_manifest.sha256`: the authors' own scorer manifest, written by their calibration
  (`integrity.sh make`). Every authors' file it lists matched it when this package was made (50 of 50; the 51st entry,
  `pristine.sha256`, is generated by `build_workspace.sh`). So the files below are the scorer that produced the card.
- `provenance/files.tsv`: per shipped file, the authors' path, both hashes and whether the file is identical.
- `provenance/paths.diff`: the exact differences for every file that is not identical. They are all of the kinds
  listed below; no scoring logic was changed.
- `provenance/authors_calib.json`: the authors' calibration result (REF 1.513, A/A, thresholds), for comparison with
  yours.

## What was changed, and why

1. **Machine paths -> variables** (`env.sh`). `/home/coder/work/p2-port` -> `$ISO_ROOT`; `/tmp/p2` -> `$P2T`
   (= your `STAGE`); `/home/coder/work/rsi` and `.../rsi/t5-isobench` (uv CPython, HF cache) -> `$ISO_ROOT`;
   `/home/coder/miniconda3/bin` -> `$HOST_PY_BIN`; in the audit hook's protected-path lists `/home/coder` -> `$HOME` and
   `/home/coder/work/cpu_pinning_main.txt` -> `$ISO_ROOT/cpu_pinning_main.txt`. Python code reads `ISO_ROOT` from the
   environment (`pairs.py`, `score_phase2.sh`, `ops_iso12380/report.py`, `smoke*.sh`).
2. **One line per shell script** that sources `env.sh` when the variables are not already set.
3. **`harness_iso12380/p2_cpus.sh`**: `CPUS` (exported as `P2_CPUS_OVERRIDE`) is returned first; the authors'
   per-pod table is used only when it is unset. (`p2_job.sh` already honoured `P2_CPUS_OVERRIDE`.)
4. **`tasks/iso12380/task.env`**: the audit-ignore regex for the benign `file -b <interpreter>` exec is built from
   `$P2T` (it named `/tmp/p2/uvpy/...`); `TASK_ENV` sets `VLLM_PORT=$PORT` (authors: empty) so parallel jobs on one
   machine cannot race for vLLM's port. Both arms get the same value.
5. **`scripts/stage_tmp.sh`**: after staging a model it pre-creates `hf/hub/version.txt` (acceptance finding: the first
   job on a newly staged machine was voided as `audit_flag` because transformers wrote that file).
6. **`harness_iso12380/dev_run_impl.sh`** (agent dev path only): its `env -i` re-exec passes the package variables on.
7. **`harness_iso12380/make_canaries.sh`**: canary C7g's literal reference path is written with `$ISO_ROOT` expanded.

Deliberately unchanged: the gate's deny-list patterns (`p2_gate_rules.py`, `kernel_gate.py`) and the redaction
pattern in `agent_view.py` still name the authors' paths. They reject candidate code that mentions `p2-port`,
`/tmp/p2`, `/home/`, `harness`, `tasks/`, `calib/` and similar; outside the authors' machines the generic patterns still
apply. Comments that mention the authors' pods are also unchanged.

New files (not the authors'): `env.sh`, `site.env.example`, `setup/setup_venvs.sh`, `setup/get_model.sh`,
`env/pkg.conf`, the locks `env/*.lock.txt`, `RUN.md`, `ENV.md`, this file, `MANIFEST.sha256` (sha256 of every package
file). The other `env/` files are the authors' build records, copied unchanged.

Not shipped: venvs, model, workspaces, calibration runs and results, caches, the authors' logs, and
`ops_iso12380/xfer/` (venv file lists the authors used to make their two pods' venv copies byte-identical).

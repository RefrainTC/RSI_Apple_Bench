# Provenance: how these files relate to the authors' copies

The authors' working copy is `/home/coder/work/p2-port/` on their pods (the shared `harness/`, `tasks/iso7822/`,
`scripts/{stage_tmp.sh,p2_job.sh,p2_cpus.sh,jobvar.py}`) and `/home/coder/work/cpu_pinning_main.txt`, plus
their venv tooling `/home/coder/work/rsi/t5-isobench/scripts/{setup.sh,setup_fix.sh,fetch.py}` (shipped as `t5scripts/`) and
the benchmark script `t5-isobench/bench/7822_parent_benchmark_prefix_caching.py` (shipped as `bench/`), read on 2026-11-24.

- `provenance/authors.sha256`: sha256 of each authors' file as found there.
- `provenance/authors_scorer_manifest.sha256`: the authors' own scorer manifest, written by their calibration
  (`integrity.sh make`). Every authors' file it lists matched it when this package was made (47 of 47, including
  `scripts/p2_job.sh`, `scripts/p2_cpus.sh` and the pinning table; the last entry, `pristine.sha256`, is generated by
  `build_workspace.sh`). See below for which card numbers this exact version produced.
- `provenance/files.tsv`: per shipped file, the authors' path, both hashes and whether the file is identical.
- `provenance/paths.diff`: the exact differences for every file that is not identical. They are all of the kinds
  listed below; no scoring logic was changed.
- `provenance/authors_calib.json`: the authors' calibration result (REF 1.480, A/A, thresholds), for comparison with
  yours.

## What was changed, and why

1. **Machine paths -> variables** (`env.sh`). `/home/coder/work/p2-port` -> `$ISO_ROOT`; `/tmp/p2` -> `$P2T`
   (= your `STAGE`); `/home/coder/work/rsi` and `.../rsi/t5-isobench` (uv CPython, HF cache) -> `$ISO_ROOT`;
   `/home/coder/miniconda3/bin` -> `$HOST_PY_BIN`; in the audit hook's protected-path lists `/home/coder` -> `$HOME` and
   `/home/coder/work/cpu_pinning_main.txt` -> `$ISO_ROOT/cpu_pinning_main.txt`. The authors' T5 root (`t5-isobench`, holding
   the HF cache and `bench/`) is `$ISO_ROOT` too. Python code reads `ISO_ROOT` from the environment (`pairs.py`,
   `score_phase2.sh`).
2. **One line per shell script** that sources `env.sh` when the variables are not already set.
3. **`scripts/p2_cpus.sh`**: `CPUS` (exported as `P2_CPUS_OVERRIDE`) is returned first; the authors'
   per-pod table is used only when it is unset. (`p2_job.sh` already honoured `P2_CPUS_OVERRIDE`.)
4. **`tasks/iso7822/task.env`**: the audit-ignore regex for the benign `file -b <interpreter>` exec is built from
   `$P2T` (it named `/tmp/p2/uvpy/...`); `TASK_ENV` sets `VLLM_PORT=$PORT` (authors: empty) so parallel jobs on one
   machine cannot race for vLLM's port. Both arms get the same value.
5. **`scripts/stage_tmp.sh`**: after staging a model it pre-creates `hf/hub/version.txt` (acceptance finding: the first
   job on a newly staged machine was voided as `audit_flag` because transformers wrote that file).
6. **`harness/dev_run_impl.sh`** (agent dev path only): its `env -i` re-exec passes the package variables on.
7. **`harness/make_canaries.sh`**: canary C7g's literal reference path is written with `$ISO_ROOT` expanded.

Deliberately unchanged: the gate's deny-list patterns (`p2_gate_rules.py`, `kernel_gate.py`) and the redaction
pattern in `agent_view.py` still name the authors' paths. They reject candidate code that mentions `p2-port`,
`/tmp/p2`, `/home/`, `harness`, `tasks/`, `calib/` and similar; outside the authors' machines the generic patterns still
apply. Comments that mention the authors' pods are also unchanged.

New files (not the authors'): `env.sh`, `site.env.example`, `scripts/post_calib.sh` (steps 1-3 of the authors'
`/home/coder/work/p2-port/scripts/after_cal.sh`, lines copied with the paths replaced; that script's steps 4-5 are
end-to-end scores and canaries, RUN.md steps 7-8), `setup/setup_venvs.sh`, `setup/get_model.sh`,
`env/pkg.conf`, the locks `env/*.lock.txt`, `env/7822_*_flashattn.sha256` (sha256 of `vllm_flash_attn` in the
authors' venvs, read on their pod 2026-11-24), `RUN.md`, `ENV.md`, this file, `MANIFEST.sha256` (sha256 of every package
file). The other `env/` files are the authors' build records, copied unchanged.

Not shipped: venvs, model, workspaces, calibration runs and results, caches, the authors' logs, and
`tasks/iso7822/vault_paths.txt` / the vault (the authors' list of their own paths to seal during agent trials).
